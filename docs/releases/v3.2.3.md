# SDAD v3.2.3

Release date: 2026-09-13
Tag: `v3.2.3`

This patch includes the accumulated workflow clarity, long-running control,
context inspection, and optional interaction-report guidance improvements.
It preserves existing project and State v2 compatibility without automatic migration.

## State v2 And Packet Identity

Existing fields and status values remain intact, including `execution_scope:
unit | packet` and `validation_for`. Completion reports distinguish the current
request, executed verification, external dependencies and owner acceptance.
`ai_complete` does not establish executed verification; evidence-ready is prose,
not a new state value. Existing cancellation and explicit-reactivation rules remain.

## SDAD Doctor 3.2

Doctor remains checkout-only and read-only. Use:

```text
python <SDAD_CHECKOUT>/scripts/sdad.py doctor [PROJECT_ROOT] --require-version 3.2.3 [--json] [--strict]
```

State-v1 unguarded calls retain report schema 1; guarded or state-v2 calls use
report schema 2. Fixes accept an initial UTF-8 BOM, expand home-relative CLI roots,
reject invalid relative paths, inspect repeated visible ledger sections without
counting fenced examples, preserve valid owner gates beside malformed entries,
and avoid applying current freshness semantics to unsupported state versions.

## Handoff, INDEX, And Ledger Consistency

`current_handoff` remains the last declared resume checkpoint. Compare it with
current owner intent, SPEC and source before resuming; cancelled work never
reactivates from old handoff prose. Evidence has one authoritative home, with
short scoped summaries and links elsewhere. Existing project evidence locations
take precedence over the optional `docs/sdad/evidence/<packet-id>.md` convention.

## Targeted Routing

The router combines intent, reads, conditional updates and default omissions.
`routed_docs` remains an eligible selection set, not a read-all instruction.
The optional read-only `scripts/sdad_context.py` offers inventory and bounded
reads with source identity checks. It does not enforce other tools' read limits.
Six generated adapters retain the 6,000-character ceiling; the largest is 5,678.
Optional interaction Markdown guidance separates requests, AI reports,
corrections and observed results without direct transport or automatic approval.

## Migration Preview And Upgrade Compatibility

The read-only preview and existing project interfaces remain. Adoption is
explicit; no global installation, state migration or automatic project update
is performed. No-clone sources pin immutable baseline `04a3e24569758237b702c5a2fbc6094a186d6cb0` and the seven
Git-blob SHA-256 values in `install-sources.json`.

## Verification Evidence

The local Windows gate ran 492 tests, with three environment-dependent skips
(489 passed). Repository validation, six generated surfaces and prompt parity
are checked again for the release. The fresh-context task benchmark compared
24 sessions across frozen before/after candidates; all final independent
function checks passed. Command output decreased by 16.8% and 11.6% in two
comparisons. These small synthetic runs do not establish general productivity
or months-long stability. See [the bounded experiment report](../v4/WORKFLOW-CLARITY.ko.md).
The tag's GitHub validation run provides the Windows/Linux release evidence.

## Known Limitations

Doctor green does not prove correctness, productivity, or owner acceptance.
Some AI sessions still read large documents in full or choose `ai_complete`
despite reporting successful local tests. Evidence files still need deliberate
maintenance. The optional interaction work does not establish completed 4.0
user evaluation, direct agent integration, or a new state schema.
