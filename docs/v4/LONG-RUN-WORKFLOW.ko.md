# 장기 이용·개발 개선

상태: 2026-09-13 로컬 후보 개선과 실제 새 세션 5회 검증 완료. 전역 설치·발행·사용자 수락과는 별개다.

## 범위

이전 실제 실행에서 관리 문서 누적, 500줄 읽기 한도 초과, 관리 파일 검사기
부재가 드러났다. 이번에는 선택적 읽기·크기 점검 도구와 현재 기록 유지·안전한
이력 분리 절차를 개선한다. 시작 커널에 규칙을 추가하거나 state 스키마를
변경하지 않는다. 기존 미커밋 작업과 사용자 평가·출시 경계는 보존한다.

## 확인할 결과

- 필요한 heading/page만 읽고, 읽는 사이 원문이 바뀌면 이어 읽기를 거부한다.
- 관리 파일이 커졌음을 내용 전체 노출 없이 확인한다.
- 이력 정리 후에도 미해결 항목·현재 제약·근거 링크와 원본 이력이 남는다.
- 새 세션의 연속 정정에서 기존 기능·검증·권한 경계를 유지한다.
- 과거 핸드오프와 현재 요구가 다를 때 현재 요구·소스·SPEC을 대조한다.
- 실제 모델 실행과 독립 코드·문서 검사를 분리하고 파일 크기·명령·사용량을
  남긴다. 짧은 반복 실험을 수개월 신뢰성이나 생산성 증거로 확대하지 않는다.

## 구현

`scripts/sdad_context.py`를 추가했다. 외부 패키지 없이 기존 경로·상태 판독기를
재사용하며 파일을 변경하거나 검증 명령을 실행하지 않는다.

- `inspect`: 현재 관리 파일·활성 SPEC·선언된 핸드오프의 크기와 해시를 표시.
  500줄/50KB 초과는 부분 읽기, 2,000줄/200KB 초과는 분할 검토를 제안한다.
  내용 전체를 응답에 넣거나 미선택 SPEC·이력 폴더를 순회하지 않는다.
- `read`: 정확한 heading 또는 줄 범위로 기본 100줄을 읽는다. 페이지는
  500줄과 JSON 표현 비용을 포함한 50KB 이내이며, 1MB 초과 파일은 거부한다.
- 이어 읽기에서 `next_start`와 `--expect-sha256`을 사용하면 원문 변경을
  감지한다. 중복 heading·잘못된 경로·잘못된 UTF-8·한도를 넘는 단일 줄은
  오류로 알려준다. 내용 일부만 읽었다는 사실과 다음 페이지를 명시한다.

크기 제안은 작업 완료나 자동 보관 허가가 아니다. Doctor의 기존 구조 검사와
별도로 사용한다. 프로젝트에 함께 배치할 때는 `sdad_validator` 패키지와
실제 실행 경로를 함께 제공한다. 사용 예는 [컨텍스트 관리 문서](../context-stability.md)에 있다.

기존 문서 관리 playbook에는 현재 결과의 갱신, 완료 이력의 원문 보존,
미해결 항목·현재 제약 유지, 링크 확인과 수정 전 원문 재확인을 구체화했다.
실행 중 구현 노트의 누적을 발견해, 설계 결정과 반복 검증 기록을 구분하는
안내도 템플릿과 playbook에 보완했다. 항상 읽는 커널의 크기는 늘리지 않았다.

## 실제 연속 실행

동일한 합성 프로젝트에 완료 이력 100건, 미해결 TODO/발견 사항 각 1건,
이전 이력을 가리키는 링크를 넣었다. 초기 strict Doctor는 오류·경고 0건이다.
같은 `gpt-6-astra/high`, Codex CLI `0.154.0-alpha.6.2`로 매번 새 세션에서
작업했다. auth-only 임시 홈과 원시 로그·명령·단계별 스냅샷을 사용했다.

| 단계 | 작업 | 독립 코드 검사 | TODO 줄 수 | 구현 노트 줄 수 |
| --- | --- | --- | ---: | ---: |
| 시작 | 완료 이력이 누적된 상태 | 사전 fixture 준비 | 710 | 5 |
| 1 | 완료 이력 분리 | 4/4 | 17 | 25 |
| 2 | None 삭제/보존 옵션 추가 | 7/7 | 17 | 51 |
| 3 | 과거 핸드오프가 있는 상태에서 키워드 전용 옵션으로 정정 | 8/8 | 17 | 93 |
| 4 | 현재 결과와 한계 설명만 요청 | 8/8, 파일 변경 0 | 17 | 93 |
| 5 | 구현 노트의 반복 검증 이력 분리 | 8/8, 코드 변경 0 | 17 | 25 |

첫 정리에서 TODO가 39,222바이트에서 813바이트로 줄었고, 원문 이력 100건과
T-PRESERVE/F-PRESERVE의 문구·미해결 상태, HIST-042 링크를 유지했다.
기존 주소에는 새 보관 위치를 가리키는 호환 링크를 남겼다. 코드는 변경하지 않았다.

두 번의 기능 변경에서도 현재 SPEC·소스와 과거 핸드오프를 대조하고 기존
보존·입력 불변 조건을 유지했다. 두 정정과 설명 세션의 도구 응답에는 보관된
100건의 이력 본문을 다시 출력하지 않았다. 각 단계 strict Doctor는 오류·경고
0건이며, 미해결 항목과 보관 기록도 계속 남았다. 설명 세션은 읽기만 수행했다.

독립 검사기는 AI가 수정할 작업 폴더 밖에 있으며 **각 단계 스냅샷**을 검사한다.
검사기 자체도 옵션 무시·잘못된 위치 인자 허용·입력 변경·함수 누락을 거부하는
4개 테스트로 확인했다. 모델이 보고한 테스트 수만으로 성공을 판정하지 않았다.

## 실행 중 추가로 발견한 문제

TODO는 작아졌지만 구현 노트는 25→51→93줄로 증가했다. 현재 결과를 갱신하라는
일반 지침만으로는 기존 프로젝트의 실행 기록 습관이 사라지지 않았다.
설계 결정과 검증 기록을 구분하는 구체적인 안내를 보완하고, 다섯 번째 새
세션에서 노트 원문을 보존하며 현재 안내만 남기는 정리를 검증했다.

노트는 93줄에서 25줄로 줄었다. 원래 7,002바이트 전체가 별도 이력 파일의
607바이트 위치부터 그대로 남았으며 SHA-256도 일치했다. 짧은 현재 노트는
현 제약, 최신 검증 링크, 옛 주소의 호환 링크를 갖는다. 신규 검증은 별도
근거 파일에 두었다. 기존 이력·미해결 문구와 링크를 유지했고, 코드·테스트·
도구는 바꾸지 않았다. 마지막 단위 테스트 13개와 독립 사례 8개를 통과했으며
AI와 평가 측의 strict Doctor 모두 오류·경고 0건이었다.

새 도구의 단위 검사는 9개이며, 전체 회귀는 489개 중 486개 통과·3개 환경상
제외다. 저장소 검증, 어댑터 생성 일치와 diff 공백 검사도 확인했다. 최신 도구로
최종 스냅샷을 다시 점검해 활성 SPEC까지 포함되는 것을 확인했다. 커널 크기는
유지했으며, 기존 체크아웃과 사용자 평가 기록은 변경하지 않았다.

## 한계와 적용 판단

이 실험은 여러 달의 이용이나 생산성 A/B가 아니다. 도중에 JSON 출력 한도를
보완했고, 발견된 노트 누적에는 별도 지침과 추가 작업을 적용했다. 조건 변경과
도구 해시는 원시 기록에 남겼다. 지침 하나의 효과나 속도 향상을 분리해서
추정하지 않는다.

현재 도구는 선택적으로 사용하는 점검·읽기 도구다. 다른 읽기 명령까지
자동 통제하거나 여러 작업자의 동시 편집을 잠그지 않는다. 활성 SPEC·노트의
변경 이력도 계속 관리해야 하며, 다음 현장 검증은 수십 회 정정과 동시 작업에서
근거 손실·링크 파손·문서 크기·읽기 비용을 함께 확인하는 것이다.

로컬 근거: `SDAD-long-run-20260913`의 `protocol.json`, `runtime-update.json`,
`notes-followup-protocol.json`, `summary.json`, `runs/*/`에 실행·변경 조건·검사
결과·원문 스냅샷을 보존한다. 실행 도구는 이 PC 경로에 맞춘 평가 도구이며,
새 `sdad_context.py`의 일반 프로젝트용 인터페이스와 구분한다.
