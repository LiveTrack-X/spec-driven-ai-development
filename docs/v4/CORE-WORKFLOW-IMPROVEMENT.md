# SDAD core workflow refinement

Status: Local candidate implemented and exercised; not released or owner-accepted.

The owner requested protocol improvements and actual execution on 2026-09-13,
including a candid assessment of observed friction and longer-term problems.
This slice changes SDAD guidance and its examples, not companion UI or state v2.

## Acceptance boundary

- Resolve missing-handoff recovery consistently in the kernel and playbooks.
- Compare intended outcomes/constraints against a proposed plan before affected
  implementation; surface meaningful assumptions without routine approval waits.
- Close each applicable requirement with outcome, evidence and remaining limits.
- Reconcile a correction with affected plan/TODO/evidence before continuing.
- Keep the startup budgets and existing authority/acceptance boundaries intact.
- Exercise actual agent actions in synthetic repositories and independently
  execute fixture checks; preserve failures and distinguish harness/provider
  failures from behavioral outcomes. Use the same model/configuration per pair.

## Evaluation boundary

Freeze the pre-refinement candidate, then compare its instructions with the
refined instructions on bounded tasks. Include implementation, read-only review,
blocked validation and fresh-session correction/re-entry. Track observable
changes, independent tests, recorded commands, repeat work, documentation volume
and measured usage; no self-assigned model success score.

Keep user-global skills, memories, MCP and unrelated instructions out of the
pilot. Keep raw logs and exact fixture/instruction hashes locally. A small
single-provider pilot can expose failures and costs, but cannot establish
general productivity or long-term reliability. No release, deployment or
machine-global installation is authorized by this work.

## Observed result and disposition

The six-session comparison found correct code and read-only boundaries in both
conditions, but both invented an unsupported state value. Two targeted follow-up
sessions checked write-site enum guidance, concise evidence, finding grammar and
an available local Doctor. The final correction passed independent code checks
and strict Doctor with zero findings. This is not a general effectiveness claim.

Keep the recovery, criterion closure and correction clarifications. Keep the
state/finding examples paired with runtime-contract tests. Refine document cost
in field use; do not add more always-loaded rules to solve every observed issue.

[the execution report](CORE-WORKFLOW-PILOT.ko.md).
