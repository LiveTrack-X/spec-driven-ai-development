# SDAD 작업 규칙 명확화·문서 부담 감소

상태: 2026-09-13 로컬 후보 구현·회귀 검사와 고정 조건의 24개 세션 비교 완료.
전역 설치·발행·사용자 수락과는 별개다.

## 변경과 호환성

- INDEX에서 작업 의도별 읽기·조건부 갱신·기본 생략을 함께 안내한다.
- 완료 보고를 현재 요청, 실행된 검증, 외부 의존 사항, 사용자 수락으로 구분한다.
  State v2의 상태값이나 필드를 추가하지 않고 기존 의미를 유지한다.
- 프로젝트의 기존 검증 기록 위치를 먼저 사용한다. 없을 때만 지속적인 근거가
  필요한 최초 시점에 `docs/sdad/evidence/<packet-id>.md`를 만들고 TODO에서 연결한다.
- 한 사실의 권위 있는 원본과 다른 위치의 짧은 요약·링크를 구분한다.
- 과거 핸드오프를 현재 소스·SPEC과 대조하고, 변경의 영향에 따라 근거를 재사용한다.
- 설명·계획 응답의 단계별 N/A 나열과 읽은 문서 목록의 반복을 없앤다.
- 공개 작업 루프와 설치 스킬의 설명도 새 보고 기준에 맞췄다.

기계가 읽는 핸드오프 안내 줄, State v2, 기존 상태값, CLI 인자와 JSON 출력은
유지한다. 새 근거 경로는 문서 관례이며 자동 보관·승인·상태 승격 기능이 아니다.
미해결 작업을 숨기거나 현재 완료 조건을 축소해 상태를 좋게 보이게 해서는 안 된다.

| 시작 문맥 | 이전 | 개선 후보 |
| --- | ---: | ---: |
| 가장 큰 어댑터(Cursor), 문자 수 | 5,996 | 5,678 |
| Codex 어댑터 + INDEX + 상태 템플릿, 문자 수 | 11,209 | 10,967 |

기존 6,000자 한도는 지켰다. 5,400자 축소 목표에는 278자 미달했다.
권한·정정·취소·외부 지시·검증 경계를 상시 유지했으며, 수치 달성을 위해
이를 추가 삭제하지 않았다. 문자 수 감소는 모델 토큰이나 생산성 개선의 증명이 아니다.

## 회귀 검사

- 전체 unittest: 492개 중 489개 통과, 환경 조건에 따른 3개 생략.
- 저장소 검사, 어댑터 6개 생성물 동기화, `git diff --check` 통과.
- 새 안내 계약 검사 3개에는 8개의 경계 제거 변형을 포함한다.
- 핸드오프 안내 줄 검사는 부분 문자열이 아닌 정확한 한 줄을 검사하도록 강화했다.
- 독립 기능 판정기는 올바른 구현과 입력 변경·옵션 무시·위치 인자 허용·과거 None
  동작·얕은 교체 대신 깊은 복사라는 잘못된 구현을 대상으로 6개 자기 검사를 통과했다.

문서 계약 검사는 안내의 존재·연결과 삭제 회귀를 확인한다. 실제 AI의 의미 이해나
행동 준수까지 보장하지 않는다. 기능 판정은 각 세션의 보존된 소스 스냅샷에 실행한다.

## 실제 AI 비교 방법

동일한 `gpt-6-astra/high`, Codex CLI `0.154.0-alpha.6.2`, 동일한 Python 검증
런타임으로 개선 전·후 후보를 비교한다. 각 후보에서 6단계 연속 작업을 두 번
수행하며, 단계마다 새 세션을 사용한다. 두 독립 실행을 동시에 진행한다.

1. 확장 키를 버리는 작은 설정 병합 버그 수정.
2. None 삭제/보존 옵션으로 요구사항 정정.
3. 파일 변경·새 테스트 실행 없는 설명 요청; 취소된 배포는 재개 금지.
4. 오래된 핸드오프와 미커밋 소스 회귀를 주입한 뒤 키워드 전용 옵션으로 수정.
5. 외부 검증이 현재 필수 조건인 경우와 별도 후속 작업인 경우를 각 반복에 적용.
6. 완료 이력·검증 기록 정리; 원문 100건, 미해결 항목, 취소 기록, 링크 보존.

각 세션의 명령·원시 로그·응답·변경 전후 해시·스냅샷을 보존한다. auth-only 임시
홈을 사용하고 추가 도구·전역 스킬·기억을 비활성화한다. 저장소 범위 제한은
지시 수준이며 OS 차원의 격리를 입증하는 것은 아니다.

후보 지침은 첫 세션 전에 고정했고 실행 중 변경하지 않는다. 공개 안내 및
검사·보고서의 후속 정리는 모델에게 제공된 동결 지침을 변경하지 않는다.

사전 준비에서 핸드오프 안내 줄 끝에 추가 설명을 붙이면 Doctor가 경고한다는
점을 확인했다. 줄 형식을 복원하고 설명을 별도 문단으로 옮긴 뒤 모든 초기
fixture의 strict Doctor 오류·경고 0건을 확인했다. 실패한 준비본도 보존했다.
원문 보존 판정은 플랫폼 줄바꿈을 가정하지 않고 시작 해시와 일치하는 원본
바이트를 기준으로 한다.
실행 중 독립 판정기에 중첩 객체의 동일성 검사도 추가했다. 모델 지침은 변경하지
않았으며 이미 완료된 모든 스냅샷에 강화된 판정기를 다시 적용했다.

## 비교 결과

24/24 세션이 종료됐고 준비·인증 실패나 시간 초과로 제외한 세션은 없다.
각 최종 스냅샷의 독립 기능 판정은 모두 통과했다(단계별 5/8/8/9/9/9개 사례,
네 연속 실행 합계 192개 사례). 최종 strict Doctor도 24개 모두 오류·경고 0건이다.
수정 전 회귀 실패, 중간 Doctor 경고, 셸·검증 스크립트 오류는 원시 로그에 남겼다.
이 최종 통과 수가 모든 중간 명령의 성공이나 모든 규칙 준수를 뜻하지 않는다.

| 완료 세션 | 6 | 6 | 6 | 6 |
| 정리 직전 TODO 줄 수 | 730 | 535 | 610 | 544 |
| 정리 후 TODO 줄 수 | 32 | 23 | 31 | 24 |

현재 관리 기록 수치는 TODO·findings·구현 메모·state의 합이며, 전체 문서량이나
모든 근거 파일 크기가 아니다. 초기 TODO에는 100건의 완료 이력이 포함돼 있다.
명령 출력량은 명령 결과 전체의 문자 수로, 파일 읽기량·모델 토큰·비용과 같지 않다.
실제 읽기는 명령과 출력의 절·본문을 대조했다. 메타데이터·해시·경로 목록을
본문 읽기로 세지 않았으며, `manual-read-review.json` 목록은 확인된 부분 읽기의
하한이다. 자동 `read-candidates.json`은 추가 검토 대상이지 확정된 전체 읽기 목록이 아니다.

두 비교의 명령 출력량은 각각 16.8%, 11.6% 감소했다. 다만 개별 첫 수정에서는
개선안 출력이 더 큰 경우도 있었고, 필수 문서의 최소 읽기가 항상 지켜진 것은 아니다.
시간·사용량은 관측값으로 보존했지만 두 반복으로 일반적 속도·생산성 향상을 주장하지 않는다.

- 설명 전용 4개 세션: 파일 변경·새 테스트 실행 없음. 기존 결과와 현재 관찰을 구분했다.
- 재개 4개 세션: 주입된 미커밋 회귀를 수정하고 과거 통과 기록을 현재 근거로 쓰지 않았다.
- 외부 의존 4개 세션: 실제 가용성 명령의 종료 코드 3을 실패/미확인으로 유지했다.
  필수 조건인 두 세션은 전체 결과를 blocked로 두고, 별도 후속 작업인 두 세션은
  로컬 결과와 외부 미확인을 구분했다. 서비스 연결·설정·배포는 실행하지 않았다.
- 모든 세션에서 소스 판정, 사용자 초안·보호 런타임, 미해결 T/F, 취소 상태를 보존했다.
  HIST 100건의 내용과 HIST-042의 실제 대상도 유지했다. 호환 앵커를 경유한 연결을 포함한다.
- 네 정리 세션 모두 정리 직전의 원본 파일을 독립적으로 바이트 단위 복구했다
  (각각 2/3/4/3개 파일). 초기 이력과 비교하면 개선 전 1의 외부 단계에서 CRLF가
  LF로 바뀌어 초기 바이트 동일성은 깨졌다. 내용 유실과 정리 중 원문 유실은 없었다.
- 불필요한 승인 재질문만 남기고 작업을 멈춘 사례, 외부 성공·사용자 수락의 허위 주장은
  관찰하지 않았다. 양쪽 모두 통과했으므로 이 항목의 정확도 우위를 주장하지 않는다.
- MCP·provider error·turn.failed 이벤트와 JSON 파싱 실패는 없었다. 일반적인
  `unauthorized` 탐지 문자열은 출력된 금지 규칙에서 나온 것이며 인증 실패가 아니다.

## 채택 판단과 남은 문제

기록 위치·요약·근거 재사용·보고 방식 개선은 로컬 후보로 유지한다. 두 반복에서
관리 기록 누적과 명령 출력이 줄었고 기능·권한·미해결 항목 보존의 회귀는 관찰하지 않았다.
기능 정확성, 승인 판단, 핸드오프 처리의 개선 우위는 양쪽 모두 통과해 입증하지 못했다.

상태 표현은 해결됐다고 판정하지 않는다. 개선안 2는 첫 수정에서 로컬 테스트 9개를
통과했지만, 외부 미확인 항목에 대한 `packet.open-todo`/`packet.open-finding` 경고를
피하려고 `ai_complete`를 선택했고 이후 6개 세션 내내 유지했다. 개선안 1과 두 기준선은
같은 로컬 범위를 `software_verified`로 표현했다. 개선안 2도 실행된 테스트와 외부
미확인·미수락을 정확히 보고했으므로 허위 검증은 아니지만, 상태만 보는 사람에게는
불일치가 남는다. Doctor의 구조적 연결과 의미상 완료 범위를 조정하는 판단이 여전히 어렵다.

또한 일반 Get-Content 등으로 500줄을 넘는 TODO 전체를 읽으려는 동작과 선택적
원장까지 여는 동작이 두 조건에서 남았다. 문서 지침과 선택적 읽기 도구는 이를
기술적으로 강제하지 않는다. 기본 읽기 경로 단순화가 불필요한 읽기를 없앴다고 주장하지 않는다.

검증 근거 파일 자체도 정정마다 커질 수 있다. 개선안 2의 근거 파일은 정리 전
21,740바이트까지 증가했다가 1,624바이트로 줄었다. 기록 위치 분리와 현재 요약 유지,
필요할 때의 보존·정리는 함께 필요하다. 현재 관리 파일 밖으로 이동했다고 기록
총량이 사라지는 것은 아니다.

이 실행 중 후보 지침을 추가 수정하거나 24개 제한 밖의 모델 세션을 실행하지 않았다.
상태 문제는 다음 설계 판단의 근거로 남긴다. 관찰된 것은 한 종류의 상태/후속 항목
상호작용이며, 두 종류 이상의 표현 불가능 사례를 확인한 것은 아니므로 State v3를
자동 착수할 근거로 삼지 않는다. 수개월 안정성, 다른 모델·실제 제품에서의 효과도 미검증이다.

## 근거 위치와 재실행

실행 자료는 로컬 산출물 폴더 `SDAD-clarity-20260913`에 있다. `baseline/`과
`candidate/`가 동결된 후보이고 각각의 manifest가 파일 해시를 기록한다.
`pilot.py`, `oracle.py`, `test_oracle.py`, `summarize.py`, `protocol.json`과
`runs/<단계>-<조건>-<반복>/`에 실행·판정 근거가 있다.
`protocol-final-unittest.log`는 최종 전체 회귀 결과다.

`summary.json`/단계별 `extended-audit.json`, `semantic-review-1.json`과
`semantic-review-2.json`은 구조·내용 판정과 응답 검토를 분리한다.
`compaction-recovery*.json`에는 독립 원문 복구 비교가 있으며,
`implementation-diff.patch`는 기존 미커밋 변경을 제외한 이번 작업의 차이다.

재실행은 새로운 산출물 폴더에서 같은 동결 후보·CLI·프롬프트를 사용한다.
기존 실행 폴더나 인증 정보를 복제·덮어쓰지 않는다. 새로운 모델/CLI/후보로
바꾸면 별도의 비교 조건으로 기록하고 이전 성공 결과에 합산하지 않는다.
